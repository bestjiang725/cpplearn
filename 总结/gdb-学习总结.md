## 一、核心心智模型(面试必考)

### 1. gdb 是时间停止器,不是监控埋点
竞赛 debug 靠 cout 打印 = 在程序里埋监控。gdb 换个思路:**程序正常跑,你在任意一行把时间暂停**,暂停后随意观察。

### 2. 三个问题 → 三个命令
| 问题 | 命令 |
|---|---|
| 现在停在哪? | 断点 + `list` |
| 变量是多少? | `print` |
| 谁调用的谁? | `bt`(backtrace) |

### 3. 两个编译参数是前提
```bash
g++ -g -O0 程序.cc -o 程序
```
- `-g`:往可执行文件塞**地图**(符号表)——每行机器码对应源文件第几行、变量名
- `-O0`:关优化——优化会重排代码,单步会乱跳

### 4. 断点停下的那一行,**还没执行**
证据:`int i;` 的下一行 `print i` 看到的是垃圾值 0/随机值,`for` 行执行后才是真值。

### 5. 帧 = 一次函数调用,栈是 LIFO
- 每次调用函数:压入一帧(参数、局部变量、返回地址)
- 每次 return:弹出这一帧,回到调用者的返回地址
- `bt` 显示的是**"此刻谁在等谁"**,不是历史——已返回的函数不在栈上
- `frame N` 可以在帧之间穿梭

### 6. 断点是"地点侦查",watch 是"目标侦查"
- `break` = 走到某行停(不管变量)
- `watch` = 某变量被写时停(不管地点)——直接指认凶手行

## 二、命令速查表

### 基础(gdb 命令都能用不歧义前缀缩写)
```gdb
gdb -q ./程序           # -q 跳过版本废话
break main / b 行号     # 打断点
run / r                # 从头跑,遇断点停
next / n               # 下一行,不进入函数(跨过去)
step / s               # 下一行,进入函数(钻进去)
print 变量 / p 变量     # 看值($1 = ...)
bt                     # 调用栈
info locals            # 当前函数全部局部变量
list                   # 看源码
continue / c           # 跑到下个断点/结束
quit / q               # 退出
Ctrl+C                 # 中断运行中的程序(卡死时救命)
```

### 进阶
```gdb
watch 变量              # 变量被写的瞬间停下(Old value → New value)
b 行号 if 条件          # 条件断点,只停"要出事"的那次
frame N                # 切换到第 N 帧
generate-core-file core # 拍现场快照
gdb ./程序 core         # 事后破案:带快照回现场
```

### 段错误标准破案流程(90% 崩溃这样查)
```
gdb -q ./程序
(gdb) r                          # 程序崩溃 → Program received signal SIGSEGV
(gdb) bt                         # 指认案发地 + 完整调用链
(gdb) frame N                    # 穿梭各帧看状态
```

## 三、三种病状,四种武器(总表)

| 病状 | 现象 | 武器 | 流程 |
|---|---|---|---|
| 结果错 | 跑得完,输出不对 | break + n/s + p | 断点逼近,单步盯变量 |
| 变量被偷偷改 | 看起来正常 | **watch** | 盯变量,被写瞬间指认凶手行 |
| 段错误 | 崩溃 | gdb r 接住 + **bt** | 崩溃停下,bt 指认,frame 穿梭 |
| 卡死 | 不动不报错 | **Ctrl+C** + bt | 打断,看卡在哪一行 |
| 事后破案 | 只有 core 文件 | `gdb ./prog core` | 快照回现场 |

## 四、core dump:崩溃现场的照片

**本质**:崩溃瞬间,内核把进程的**内存 + 寄存器完整快照**存盘。只能回到崩溃那一刻,不能回放过程。

**真实服务器流程**(本机 WSL 有怪癖,见坑 7):
```bash
ulimit -c unlimited    # 默认 0 = 关闭,先开开关
./程序                  # 崩溃 → 生成 core 文件
gdb ./程序 core         # 事后破案
```

**场景**:线上程序崩了,gdb 不在场——工程师拿到的只有 core 文件,破案全靠它。这是与 AI Infra 工作日常最贴近的技能。

## 五、关键概念对照

| 概念 | 一句话 |
|---|---|
| SIGSEGV | 访问了不属于你的内存(空指针/野指针),OS 当场枪毙 |
| 段错误 vs 越界写 | 越界写是暗杀(埋雷不炸),段错误是当场枪毙 |
| UB(未定义行为) | 标准说"后果自负";实际发生什么取决于内存布局——换环境随时爆 |
| struct 连续布局 | 成员按声明顺序连续存放 → arr[4] 必然踩到下一个成员 |
| 下标本质 | `a[i]` = 起始地址 + i×元素大小,纯算术,**没有越界检查** |
| O(2ⁿ) 证据 | fib(5) 断点命中 15 次 = 递归爆炸的直观计数 |

## 六、踩过的坑(最值钱的部分)

| 坑 | 教训 |
|---|---|
| 分页器按 q 退出整个 gdb | 按 **Enter** 翻页;启动用 `gdb -q` 直接跳过 |
| 在 bash 里敲 gdb 命令 | 永远看提示符:`(gdb)` 才认 gdb 命令,`$` 是 bash |
| 每次问 debuginfod y/n | 输入 n;一劳永逸:`echo "set debuginfod enabled off" > ~/.gdbinit` |
| 退出问 Quit anyway? | 程序还在跑,输入 y 确认 |
| 天真版越界程序跑起来完全正常 | UB 埋雷不炸:测试全过 ≠ 没有 bug |
| WSL 的 timeout 退出码不可靠 | 判断卡死要看"进程是否还活着",别信退出码 0 |
| 二进制文件不翼而飞(day10) | 源码才是资产,二进制只是产物——重编即可 |
| 栈上局部变量越界没炸 | 栈布局是编译器说了算;要确定性复现用 struct 装一起 |
